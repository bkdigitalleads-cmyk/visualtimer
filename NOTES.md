- 2026-11-20: 1.0.0 build 4, the paywall now appears over sheets. Branch claude/timer-paywall-over-sheets from main after PR 3 merged.
  - The bug (from the owner's TestFlight test of build 3, and listed under Noticed, not changed in build 3): with Settings open as a free user, See Pro did nothing. Settings is a pageSheet Modal; the paywall Modal was mounted at the app root, and iOS will not present a second modal from the root while a sheet is already presented. The same was true of every askPro inside a sheet: Settings' child lock switch, and the locked scenes and colors in the saved timer and routine editors.
  - The fix:
    - src/ui/Layer.tsx: ModalLayer. Every sheet (the kit's Sheet and BottomSheet, the only Modals besides the paywall) wraps its content in it. It registers the sheet while it is open, with its depth, and mounts a copy of the paywall inside the sheet's own Modal, which iOS presents from that sheet. App.tsx hands the paywall in once (registerPaywallHost), so the kit does not import the paywall.
    - src/paywallGate.ts (pure, tested): askPro opens the copy in the sheet on top (topLayer in src/rules.ts: deepest open sheet, latest among equals, or the root copy), joins an open paywall instead of opening a second one, and keeps it in the sheet it opened in. It resolves when the paywall's Modal calls onDismiss, after its close animation, so the caller can present its next sheet. A 900 ms fallback covers platforms without onDismiss, and a second ask while one is closing settles the first callers so the old timer cannot answer for the new paywall. If the sheet holding the paywall goes away, the paywall closes and the caller is answered.
    - src/screens/Paywall.tsx: takes its layer, shows only when it is the chosen copy (paywallShowsIn), reports onDismiss, and tags its root view with testID paywall-<layer> (used by the harness check). The root copies (first launch and the app) keep the onboarding flag and the 3 second delay; the pinned close X is unchanged.
    - src/state.tsx uses the gate; the API callers see (askPro, hidePaywall) is the same.
  - Unchanged: icon, prices, free versus Pro rules, the pinned close X, the 3 second delay on the first-launch paywall only. app.json ios.buildNumber 3 to 4.
  - Tests: tests/build4.test.mjs. It covers the top-layer rule; exactly one copy showing; See Pro in Settings opening the Settings copy; double taps; callers waiting for onDismiss; the fallback and the ask-while-closing case; the host sheet going away; the child lock explanation following the paywall from Run and from Settings. It also has a check over every Modal in the source that fails if any Modal other than the paywall does not start with a ModalLayer, so no control inside a Modal can ask for Pro without the paywall being hosted there.
  - Checked: npx tsc --noEmit clean; npm test 57/57; npx expo export --platform ios bundles; npx expo config --type introspect shows 1.0.0 (4), ios.entitlements {}, no microphone, no background modes. In the web harness (which cannot reproduce the iOS rule, since every web modal draws on top, but shows which copy opens): See Pro and the child lock switch in Settings open the Settings copy, one paywall at a time, closing it leaves Settings open; buying from the switch shows the explanation with no paywall left; a locked scene in the saved timer editor opens the editor's copy; the lock on the Run screen opens the root copy, and buying there shows the explanation, not a locked screen.

- 2026-11-17: 1.0.0 build 1, step 3 of 7: nine scenes, drawn in code with react-native-svg.
  - Why SVG and not Skia: either was allowed. react-native-svg 15.15.4 is already proven on RN 0.86 in Signature Maker, it has no CanvasKit or load-order risk, and the same components render on react-native-web, so the design renders and store screenshots come from the real scene code.
